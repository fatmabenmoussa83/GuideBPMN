Run the experiment from this page

Launcher

This page drives the local GuideBPMN API (start it with .\start_webapi.ps1). Dry run exercises the whole circuit without any LLM call (the gold diagram plays the generated draft). A real run uses the model you choose for each component (GPT-6 Luna or Claude Haiku 5.5, or any other model of OpenAI or Anthropic typed as provider:model), with the keys of the computer that runs the API; nothing is called from the browser itself.

The study: the three settings and the order of the runs
  1. First, runs 1, 2 and 3: documentation guidelines only, no learning, all 55 descriptions.
  2. Revised, runs 1, 2 and 3: each run starts from its own empty catalogue and learns on all 55 descriptions, with 3 forced next iterations. Reported: Revised i1, Revised i2 and Learned (i3).
  3. Reuse training, rounds 1 to 5: learns on the 44 training descriptions of the round, into the round's own empty catalogue, with 3 forced next iterations.
  4. Reuse test, rounds 1 to 5, after the training of the same round: first pass on the 11 test descriptions, with the documentation guidelines and the confirmed generic guidelines of the round only.
  5. Results: the card Study results below.

Stratified 5-fold cross-validation: the 55 descriptions are split into 5 folds of 11 by the complexity of the reference model (elements + pools + lanes); the models with pools or lanes are spread first. In round k, fold k is the test set and the other 4 folds (44 descriptions) are the training set. This API runs one run at a time: to run several at once, start one API per run (.\start_webapi.ps1 -Port 9001…) and change the API address above, or use .\run_kfold.ps1.

Budgets of one example (the limits the orchestrator works within; they are saved with the run and explained on the Orchestrator & budgets page)

forced: every description gets them while a failure is left
generate, validate, evaluate… each counts as one
one decision before each tool call, plus the final stop

Revised and Reuse training always start from an empty catalogue (the run's own catalogue; nothing is deleted), force the next iterations, and turn a confirmed example-specific guideline into a generic one when it can be written in general terms. Reuse test uses only the confirmed generic guidelines of its round. The guideline agents are the tool-using Retriever and Expert (Guideline learning); the runs are labelled …_agents. A learning run on a few chosen descriptions is a trial: it learns into a catalogue of its own and never into those of the study.

Model of each component (the two LLMs of the study, or “Other” to type any provider:model of OpenAI or Anthropic; ignored in a dry run)

Each learning run has its own catalogue: guidelines/learned/<generator>/agents/replicates/r1..r3/ for Revised, …/agents/folds/fold_1..5/ for Reuse and …/agents/trials/trial_<time>/ for a trial. Catalogues of two generators or two runs are never mixed, so several runs can go at the same time, each on its own API.

First | Revised i1 | Revised i2 | Learned | Reuse. Each value is the mean over the 55 descriptions, with in parentheses the sample SD between the 3 runs (First, Revised)
      or between the 5 round means (Reuse). * : different from First, paired Wilcoxon signed-rank test, p < 0.05, on the per-description mean over the runs.
      Structural validator: precision of a level = correct ÷ (correct + incorrect elements), elements summed over the models where the level applies; average = per-model mean of the levels that apply.
