Catalogues

Guidelines

The two catalogues the generator works with: the documentation guidelines, paraphrased from the OMG BPMN 2.0.2 specification and never modified by a run, and the error-driven guidelines, written by the guideline agents from verified mistakes. Every learning run has its own catalogue, which starts empty: one per Revised run (runs 1, 2, 3), one per Reuse round (rounds 1 to 5) and one per trial on a few descriptions, for each generator model. Catalogues are never mixed. An error-driven guideline is either new or refines a documentation guideline; one that could not be written in general terms is kept as example-specific.

How guidelines are learned, tested and reused

Learning (Revised runs and Reuse training).

  1. Evidence. When a failure type is detected on a description, the orchestrator passes the evidence to the guideline agents: the Structural validator's messages for T1 to T4 and, for T5 to T7, the differences measured by the Similarity evaluator (activities without a partner, missing and additional flows, order conflicts, participant differences).
  2. Retriever agent. A tool-using agent (ReAct loop, 4 tool calls: list_evidence, search_evidence, find_counterparts): it lists and searches the evidence records, selects the ones that matter for the failure type and explains the error.
  3. Expert agent. A tool-using agent (ReAct loop, 6 tool calls: read_description, find_closest_documented_guidelines, find_closest_learned_guidelines, check_wording): it reads the description, consults the closest documentation and error-driven guidelines and checks its wording, then proposes one guideline of the form “when the description states …, model …”, cites the records it relies on, and decides the relation of its guideline to the existing ones. It abstains only when the records show no difference or when the reference contradicts the description. Full detail: Guideline learning.
  4. Relation to what exists. The Expert must consult, through its tool, the 6 closest documentation guidelines (and the 4 closest error-driven guidelines of the same catalogue) before proposing, and it decides the relation: contradicts a documentation guideline (it is asked once to write one that respects the guideline; otherwise the proposal is rejected), restates one (nothing stored, the guideline is sent back), refines one, is new, or is the same as an error-driven guideline already learned (consolidated: the description is added as support). Code guards check the citations, that no label comes from the reference model, and near-copies (cosine ≥ 0.88 or word overlap ≥ 0.60). A guideline still worded in terms of its own process after one rewrite is kept as example-specific.
  5. Test in a next iteration. The guidelines learned for the description are sent back to the generator for that same description, and the new model is validated and compared again. The iterations are forced: every description does 3 next iterations while a failure is left.
  6. From example-specific to generic. When an example-specific guideline was sent back and confirmed (rule below), the Expert agent may rewrite it in general terms. The general form is checked like any guideline; if it passes, it joins the catalogue as a generic guideline (promoted), with a pointer to the example-specific one. An example-specific guideline is sent back to its own description only, never given to another description.

When a guideline is “confirmed”. Every guideline is learned from one type of error (T1–T7). The errors of that type are counted before and after the next iteration:

errors removed = errors of its type before − errors of its type after
confirmed when the errors removed are more than 0

If the new model has more errors in total (T1–T7) than the previous one, or is less valid, it is not kept: the previous model stays, so no error is removed and the guidelines sent in that iteration are not confirmed. Each guideline is judged on its own type, also when several are sent together.

Reuse (test of a round). In round k, the catalogue learned on the 44 training descriptions is frozen. The 11 test descriptions of fold k, never seen in training, receive the documentation guidelines and the confirmed generic guidelines of round k only, in a first pass without learning.

No description helps itself. A guideline is never given in Reuse to a description it was learned from: the test descriptions of a round are not in its training set.
