How to install GuideBPMN, test one description from zero, run the study from this site or from the command line, and read the outputs.

Test one description yourself, from zero, and keep every trace
  1. Install (once): Python 3.10+, pip install -r requirements.txt.
  2. Key of the LLM you will use, as an environment variable in the same terminal: $env:OPENAI_API_KEY="…" for GPT-6 Luna or $env:ANTHROPIC_API_KEY="…" for Claude Haiku 5.5. Nothing else reads it; the site never sees it. Without a key, tick Dry run on the Run page: the whole circuit runs with the reference diagram standing in for the generated draft.
  3. Start the local API: .\start_webapi.ps1 (it listens on http://127.0.0.1:8765), then open the Run page of this site.
  4. Pick a description in “Test one description from zero”, choose Revised (learning, three next iterations) or First (one pass), the LLM, and press Start. The run starts from an empty trial catalogue of its own; the catalogues of the study are never touched.
  5. Follow it: the row of the description fills in as drafts arrive; click it to see each draft next to the reference, the Structural validator level by level, the scores, every decision of the orchestrator and, for each learn, every tool call of the Retriever and Expert agents with its arguments, its result and the reason the agent gave.
  6. Download: Download this description (zip) gives every file the tool wrote for it (drafts, prompts, validator and similarity results, decisions, the full agent traces, the catalogue of the run), with a README; Download the run (zip) gives the whole run. Both come from the API on your computer.

From the command line, the same test is python run_batch.py --arm documentation --ids 07 --next-iterations 3 --force-iterations --promote-confirmed --trial --generator openai:gpt-6-luna --orchestrator openai:gpt-6-luna --retriever openai:gpt-6-luna --expert openai:gpt-6-luna; its files are in bpmn_pipeline/runs/batch_…_trial/.

Install & start
  1. Python 3.10+, then pip install -r requirements.txt (adds FastAPI, LangGraph, sentence-transformers).
  2. Keys as environment variables: OPENAI_API_KEY (GPT-6 Luna, or any other OpenAI model) or ANTHROPIC_API_KEY (Claude Haiku 5.5, or any other Anthropic model). Without a key, only dry runs (no LLM call) can start.
  3. Start the local API: .\start_webapi.ps1, then open the Run page. A second run at the same time needs a second API: .\start_webapi.ps1 -Port 9000, and that address in the launcher. Each learning run has its own catalogue, chosen automatically: guidelines/learned/<generator>/agents/replicates/rN/ for Revised run N, …/agents/folds/fold_k/ for Reuse round k and …/agents/trials/trial_<time>/ for a trial on a few descriptions, so catalogues are never mixed. The file used is saved with each run (models.json, learned_catalogue).

A dry run exercises the whole circuit with no LLM call: the reference diagram plays the generated draft. After a change to the code, restart the API and refresh the page.

Command line
cd bpmn_pipeline
python run_batch.py --dry-run                                   # circuit test, no LLM
python run_batch.py --arm documentation --no-learn --next-iterations 0 --replicate 1          # First, run 1 (also 2, 3)
python run_batch.py --arm documentation --next-iterations 3 --force-iterations --promote-confirmed --replicate 1   # Revised, run 1 (also 2, 3)
python run_batch.py --arm documentation --fold 1 --next-iterations 3 --force-iterations --promote-confirmed      # Reuse, training of round 1
python run_batch.py --arm documentation+learned --fold 1   # Reuse, test of round 1 (confirmed guidelines of the round)
python run_batch.py --arm documentation --ids 07 --next-iterations 3 --force-iterations --promote-confirmed --trial   # one description from zero, own trial catalogue
python run_batch.py --redo 06,18 --resume batch_<run>          # run again descriptions that lost a step (first attempt kept in history)
python run_batch.py --resume batch_<run>                      # continue an interrupted run
python study_report.py --generator openai:gpt-6-luna   # the study table: First | Revised i1 | i2 | Learned | Reuse
cd .. ; .\run_kfold.ps1 -Phase first | revised | train | test   # start the runs of a phase, both generators, each in its own window
.\run_kfold.ps1 -Phase resume                   # after an interruption: continue every unfinished run, redo lost steps

One model per component, each as provider:model: --generator, --orchestrator, --retriever, --expert.

Next iteration. After learning, the guidelines learned for a description are sent back to the generator for that same description. The new model is validated and compared again, and the agents learn again from it. With --force-iterations every description does the 3 next iterations while a failure is left. A guideline is marked confirmed when, after it is sent back, the errors of its own type (T1 to T7) decrease. Because this step uses the description's own reference, Revised is reported apart from First, and Reuse is measured on unseen descriptions.

Error-driven guidelines. The Expert agent classifies each proposal against the closest documentation guidelines and error-driven guidelines: documentation guideline not applied (nothing added), refines a documentation guideline, same as an error-driven guideline (the example is added as support), or new. A guideline still worded in terms of its own process after one rewrite is kept as example-specific (EXS-xxx): it is sent back to its own description only, never given to another description.

Pools. When the reference has no pool, lane or message flow (49 of the 55 examples), those added by the generator are set aside before the comparison. The scores computed on the model exactly as generated are kept as *_strict.

Budgets. Three numbers limit the work on one example: next iterations, tool calls and orchestrator decisions. They are set in the launcher or on the command line and saved with the run (models.json, limits). Their meaning and the number of tool calls an example can need are on the Orchestrator & budgets page.

Equations. Every score is defined with its equation on the Similarity evaluator page, the validator precision on the Structural validator page, and the confirmation of a guideline on the Guidelines page.

Failure types. T1–T4 come from the levels of the Structural validator. T5–T7 are detected, without any threshold, as soon as the Similarity evaluator finds a difference: a sequence flow missing or additional (T5), an activity without a partner (T6), a pool, lane or message flow missing or additional (T7).

Bonuses and penalties. Every single error costs one point at the step that finds it and earns one back at the step that shows it gone: each incorrect element of a validator level (T1–T4) and each difference from the reference (T5–T7). The orchestrator sees how many errors are still open, per type, and uses it to decide whether to learn and iterate again. Details and equations: Orchestrator & budgets.

Outputs & repository map
bpmn_pipeline/runs/batch_*/report_*.jsonaggregate metrics of the first pass: mean, std, min, max, quartiles, precision/recall, validator pass rates
bpmn_pipeline/runs/batch_*/report_*_after_rule_feedback.jsonthe same metrics after the next iterations (Revised, Reuse training)
bpmn_pipeline/runs/batch_*/per_example_*.csvone row per example, every metric
bpmn_pipeline/runs/batch_*/id_*/iterations.jsonevery draft: XML, validator verdict, scores
bpmn_pipeline/runs/batch_*/id_*/decisions.jsonthe orchestrator's decisions with their reasons, and the guideline outcomes
bpmn_pipeline/runs/batch_*/id_*/guideline_learning_history.jsonevery learn call of the description: for each failure type, every step of the Retriever and Expert agents (tool, arguments, result, reason), their final answers and what the code guards did
bpmn_pipeline/runs/batch_*/models.jsonthe settings of the run: version, model of each component, examples, budgets (limits), failure rule
bpmn_pipeline/runs/batch_*/validator_performance.jsonthe validator element by element: correct, incorrect and precision per level, first draft and kept draft
bpmn_pipeline/runs/batch_*/utility_summary.jsonbonuses and penalties of the run, by error type and by example
bpmn_pipeline/runs/batch_*/learned_guidelines_used.jsonthe catalogue frozen at the start of a run that reuses it
guidelines/bpmn_documentation_guidelines.json82 documentation guidelines (read-only)
guidelines/learned/<generator>/agents/replicates/rN/ · agents/folds/fold_k/ · agents/trials/trial_*/the catalogue of Revised run N, of Reuse round k and of each trial, with the descriptions each guideline was learned from and its tests
bpmn_pipeline/runs/_study_reports/the study tables written by study_report.py (JSON, CSV, Markdown)
validator.py · similarity_evaluator/the Structural validator and the Similarity evaluator used by every setting
bpmn_pipeline/guideline_agents_tools.py · bpmn_pipeline/guideline_agents.pythe Retriever and Expert agents (ReAct loop, tools) and the evidence records, code guards and catalogue update

The dataset is bpmn_generator_catalogue/dataset.json: 55 descriptions, each with a reference model that passes the validator.
